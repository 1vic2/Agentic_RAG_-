# 证据、评测与 Agent 可视化设计

用户已同意分阶段方案。本轮先落地可复现评测、可验证引用、工具时间线和单域名演示部署。二次检索仅作为可选实验入口；没有真实模型评测收益之前不默认启用。

## 边界

- 保留现有 FastAPI/Vue/LangGraph/Chroma/Neo4j 架构和未提交修改；不读写既有 `data/` 知识库。
- 评测数据采用项目内虚构示例文档和至少 30 个问题；CLI 显式指定知识库和 API 地址，不自动上传或索引。
- 自动化测试只验证确定性评分、引用映射和 SSE 事件归属；真实答案正确性需要用户可用的模型服务，报告将与离线测试分开。
- 引用编号依据一次回答的 evidence 顺序生成，正文 `[n]` 只在 `1 <= n <= len(evidence)` 时显示为可点击；无效标记保持普通文本。引用存在不等于事实受该来源支持。
- Agent 工具进度从执行线程进入请求专属异步队列。事件带会话 ID、工具名称、阶段、来源数量和耗时；不展示私有片段全文或工具参数。快速模式也显示向量/联网步骤。
- 指定 `kb_id` 继续约束检索；前端请求和图谱功能不变。工具错误是可见的非致命状态，最终回答仍按现有错误处理。
- nginx 前端容器代理 `/api` 到后端，Vite 开发代理继续工作；Docker 持久化目录不变。

## 顺序与验收

1. 建数据集与离线/在线评测脚本：按类别汇总证据来源命中、拒答、答案文本匹配、首选耗时；不伪称自动指标是人工正确性。
2. 编号与引用：后端提示词要求按 evidence 编号引用；前端安全渲染和点击定位；测试正常、重复、缺失编号。
3. 工具时间线：SSE `tool_start`/`tool_end`，前端展示状态；测试交错会话、失败与取消。
4. 二次检索：设计为可配置且默认关闭的受限实验；须取得阶段 1 真实基线再决定默认值。
5. 单域名部署与演示说明：Compose 包含前端 nginx，README 给出示例数据导入与评测命令。

## 取舍

不直接更换成无限 ReAct 循环，因为目前没有可用的真实质量/成本基线；不加入 LangSmith 自动上传私有内容。先用明确 evidence 合同和阶段事件展示已有工具路由，后续评测证明收益再扩大循环。
